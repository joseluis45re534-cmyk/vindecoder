# CLAUDE.md

Project conventions for carvinlookup.us (Next.js App Router + TypeScript + Tailwind, Cloudflare Pages).

## SEO / GEO conventions

- **Every public route exports `metadata` or `generateMetadata`** built with **`pageMetadata()` from `src/lib/seo.ts`** — unique title (~50–60 chars), description (≤160 chars), canonical, OpenGraph (with image) and Twitter card in one call. Next.js merges `openGraph` shallowly, so a hand-rolled block without `images` (or one that silently inherits the homepage's og:title/og:url) ships a broken preview. Titles passed to it must NOT include the brand — the root template appends ` | CarVinLookup`, and `pageMetadata` drops that suffix automatically when it would push the title past 60 chars. `metadataBase` is set once in the root layout.
- **Structured data lives in `src/lib/structured-data.ts`.** Pure functions returning plain JSON-LD objects; render with `<JsonLd data={...} />` (`src/components/JsonLd.tsx`), which server-renders `<script type="application/ld+json">` tags. Don't create a parallel `lib/schema/` directory — extend this file.
- **All indexable content must be server-rendered.** Most LLM/AI crawlers don't execute JavaScript reliably. If a page needs metadata or crawlable text, it must be a Server Component (or have its client-only parts fed initial data from a Server Component wrapper) — see the `/report/[id]` pattern below.
- **`src/app/sitemap.ts` and `src/app/llms.txt` / `llms-full.txt` pull from the same source of truth as the pages** (`BRANDS`, the AutoSEO blog via `src/lib/autoseo.ts`, `SAMPLE_REPORTS`, `TRIAL_PLAN`). Never hardcode a divergent list — add new indexable content to its source-of-truth file and these pick it up automatically.
- **`src/app/robots.ts` explicitly allow-lists AI crawlers** (GPTBot, ClaudeBot, PerplexityBot, etc. — see the file for the full, commented list) alongside the default `*` rule. When adding a new disallow, add it to the `DISALLOW` array once — it applies to every rule automatically.
- **Never fabricate stats, reviews, authors, or sources** — not in schema and not in visible copy. The placeholder "4.8" rating, fake testimonials, "268M+ records", and "Trusted by thousands" were removed (Nov 2026); only add reviews/ratings/counts back when they come from a real, citable source (e.g. a live Trustpilot profile).
- **Only claim data the report provider actually supplies.** Today the report (VinCheck API) is built on **NMVTIS title data via an approved NMVTIS data provider** (ClearVin) plus insurance/salvage, salvage-auction, lien, odometer, and NHTSA recall records. It does **not** include NICB data — cite NICB only as the free, separate VINCheck tool (and in `/most-stolen-cars`, which cites NICB's Hot Wheels report). Never call the data "official" (implies government affiliation). `/data-sources` is the source of truth for these claims and carries the NMVTIS consumer disclaimer (`#nmvtis-disclaimer`, linked from the footer) — update it whenever the provider changes.
- **Don't promise features that aren't live.** License-plate search and window-sticker lookup are **"launching soon"** until the ClearVin integration ships: `SearchForm.tsx` shows an honest notice for plate input (`PLATE_SEARCH_LIVE = false`), and the plate/sticker pages say "launching soon". When ClearVin goes live, first BUILD the plate+state branch in `SearchForm.tsx` (it's a TODO — flipping the flag alone just shows a VIN error), then flip the flag and update that copy, `/data-sources`, `llms.txt`, the sticker/plate page descriptions, and re-index the state plate tier together.
- **Pricing copy must match how billing actually works.** Report access is granted **per VIN** and every unlock starts its **own** $1 → $29/month trial subscription. Use `reportPriceLine()` / `PER_VEHICLE_NOTE` from `src/lib/pricing.ts` everywhere a price is stated (pages, schema Offer, FAQ, llms.txt, chat bot) — never say "$29/month for full report access" as if one subscription covers more VINs. `/pricing` hides the one-time Single/Bundle/Dealer plans (`SHOW_LEGACY_PLANS = false`) because checkout from that page carries no VIN, so those purchases unlocked nothing and the dealer features never existed; re-enable only after checkout can attach a VIN or credits (billing-core change — owner sign-off). `TRIAL_PLAN.features` must list only what `src/lib/vincheck.ts` actually returns (no owner counts, airbag, impound, or "verified" claims; theft is a risk FLAG, odometer is readings — not "records"/"alerts"). Sample reports (fictional VINs) never show the checkout. Each unlock currently creates a separate Stripe customer and the account portal only reaches the newest one, so cancellation copy must offer the support-email path until billing reuses one customer per email.
- **Shared authority sources live in `src/lib/sources.ts` (`SRC`).** Check pages and how-to guides cite from it; add a URL only after confirming it's live (nhtsa.gov blocks bots — confirm via search). How-to guides carry the same answer-first `answer` + `sources` fields as check pages.
- **Metadata renders in `<head>` for every user agent** (`htmlLimitedBots: /.*/` in `next.config.ts`). Next 15.2+ otherwise streams title/description/canonical/robots into `<body>` for crawlers not on its built-in list — including AI crawlers that don't run JavaScript. Don't remove it.
- **Money pages are answer-first and cited.** Each check page (`src/lib/checks.ts`) carries a 40–70-word `answer` (rendered first as "Quick answer"), explainer `sections`, verified-live `sources`, cross-links (`guides`, `resources`, every other check), and a visible "Last reviewed" date + `dateModified` (per-page `reviewed` field, falling back to `CONTENT_REVISED` in `src/lib/site.ts` — when you re-review one page, set its `reviewed` instead of bumping the global date). Follow the same pattern for new money pages.
- **Brand pages show verified NHTSA vPIC manufacturer codes.** `src/lib/brand-wmis.ts` is GENERATED by `node scripts/fetch-brand-wmis.mjs` (vPIC GetWMIsForManufacturer + DecodeWMI; a code is attached only to the makes vPIC decodes it to). Never hand-edit it or hand-type WMIs; re-run the script to refresh. The old hand-written `vinHints` field in `brands.ts` is no longer rendered. Recall tables come the same way from `node scripts/fetch-brand-recalls.mjs` → `src/lib/brand-recalls.ts` (NHTSA recalls API, exact model names only; a model NHTSA files under several names is skipped, never estimated). Re-run both scripts every few months and bump nothing by hand.
- **Lint runs in `next build`.** `eslint.config.mjs` wraps eslint-config-next 15's legacy configs with `FlatCompat`; keep `npx eslint src scripts` at zero errors or the Cloudflare build fails.
- **`SOCIAL_PROFILES` in `src/lib/site.ts` feeds Organization `sameAs`.** Add only real, live profile URLs the business controls.
- **IndexNow:** after a deploy that adds or changes pages, run `npm run indexnow` (whole sitemap) or `npm run indexnow -- /path /path` (specific URLs). The key file is `public/86403b8593158af1af147584bafdf072.txt` — public by design.
- **Cite only verified, live external URLs.** Before citing a government/authority source (NMVTIS, NICB, NHTSA, etc.), verify the URL is live via WebFetch/WebSearch — don't cite from memory.

## Programmatic content clusters (SEO)

Large SEO page-groups are **data-driven from a single source-of-truth file**; the routes, `sitemap.ts`, `llms.txt`, and nav all read from it, so you add content by editing the data file — never by hand-listing URLs. Each cluster follows the `BRANDS` → `/vin-check/[brand]` pattern.

| Cluster | Source of truth | Routes |
|---|---|---|
| Blog posts | AutoSEO Content API via `src/lib/autoseo.ts`. Off-topic posts 404 (`isOffTopic()`). `CONSOLIDATED_POSTS` 308s posts that (a) duplicate a hand-written page's intent, (b) state fabricated facts about CarVinLookup (apps, prices, testimonials), or (c) publish unsourced competitor prices — to their canonical page. `sanitizeArticle()` strips the "Powered by AutoSEO" footer, rewrites Article author/publisher to the Organization, drops AutoSEO's duplicate Organization node, and fixes in-body links (hidden/retired posts, self-links, the parked carvinlookup.com domain). `/blog` paginates AFTER filtering (`listAllArticlesWithStatus`). AutoSEO auto-publishes: `consolidatedDestination()` also auto-routes FUTURE posts matching the unreliable templates (`carvinlookup-vs-*`, `<competitor>-alternative/vs/comparison`, anything ClearVin) to the hand-written compare/alternative page; for other bad posts, add the slug to `CONSOLIDATED_POSTS`. Retired `blog.ts` slugs 308 in `next.config.ts` | `/blog`, `/blog/[slug]` |
| How-to guides | `src/lib/how-to.ts` (`HOW_TO_GUIDES`) | `/how-to`, `/how-to/[slug]` |
| Comparisons / alternatives | `src/lib/comparisons.ts` (`COMPETITORS`) — **ClearVin is a data partner (Nov 2026), not a competitor**: its pages 308 to `/compare`; never re-add it | `/compare`, `/compare/[slug]`, `/[x]-alternative` |
| Specialty checks | `src/lib/checks.ts` (`CHECK_PAGES`) | `/salvage-check`, `/lien-check`, `/vin-decoder`, `/license-plate-lookup`, … |
| Window stickers | `src/lib/window-stickers.ts` (`STICKER_MAKES`) | `/window-sticker`, `/window-sticker/[make]`, `/window-sticker/[make]/[model]` |
| Auctions (educational) | `src/lib/auctions.ts` (`DAMAGE_TYPES`, `VEHICLE_TYPES`) | `/auctions`, `/auctions/damage/[type]`, `/auctions/type/[type]` |
| Problem pages | `src/lib/problem-pages.ts` + `/most-stolen-cars` | `/problems`, `/most-*-cars`, `/worst-cars-to-buy` |
| Calculators | interactive client components in `src/components/calculators/` | `/auto-loan-calculator`, `/lease-calculator`, `/depreciation-calculator` |

Rules when adding to a cluster:
- **Add the entry to the data file, then verify `sitemap.ts` + `llms.txt` include it** (both import these lists — a new entry should appear automatically).
- **No self-cannibalization.** Don't create two pages targeting the same keyword/intent (e.g. a `/how-to/spot-odometer-rollback` guide *and* a `/blog/how-to-spot-odometer-rollback` post). Pick one canonical home and cross-link.
- **No fabrication (reinforced).** Competitor comparison pages stay to general, widely-known positioning — never invent a competitor's price/feature. Window-sticker and check pages describe what the report/sticker contains and funnel to the live VIN lookup; they never hardcode a specific car's MSRP/specs. Listicles cite real public sources (e.g. NICB for `/most-stolen-cars`) with a live link, or are written as educational explainers when no authoritative per-model data exists.

### Phased indexing — deep model tiers are intentionally `noindex` (crawl-budget)

The two deepest, most templated tiers — **`/window-sticker/[make]/[model]`** and **`/vin-check/[brand]/[model]`** (~500 pages combined) — are deliberately **`robots: { index: false, follow: true }`** and **omitted from `sitemap.ts`**. Since Nov 2026 the same applies (via `NOINDEX_FOLLOW` from `src/lib/seo.ts`) to **`/window-sticker/[make]`** (~100 words/page, and sticker data isn't live until ClearVin) and **`/auctions/damage/[type]` + `/auctions/type/[type]`** (~200 words/page); their hubs `/window-sticker` and `/auctions` stay indexed. Re-index those two tiers only after each page is enriched with genuinely unique content. The **51 `/license-plate-lookup/[state]` pages** are noindexed and out of the sitemap too (near-identical templates for a feature that isn't live); the `/license-plate-lookup` hub stays indexed. Re-index them when plate search ships with state-specific content. Reason: on a young, low-authority domain, ~500 near-duplicate templated pages triggered Google's *"Discovered – currently not indexed"* (crawl budget rationed; the pages were never even crawled). Concentrating crawl budget on the ~230 higher-value pages (make/brand hubs, checks, blog, how-to, compare, states, auctions, core) gets those indexed faster. The pages still render and stay internally linked for users; `follow: true` keeps link equity flowing.

- This is **temporary and deliberate** — not a bug. Don't "fix" it by re-indexing these tiers without a reason.
- **To re-open once the domain has indexing authority** (months out, once the hubs + blog rank and Search Console shows healthy indexing): remove the `robots` block from `src/app/(site)/window-sticker/[make]/[model]/page.tsx` and `src/app/(site)/vin-check/[brand]/[model]/page.tsx`, and restore the `stickerModels` + `modelVinChecks` blocks in `sitemap.ts` (see the comment there). It's a clean revert of commits `45961ed`/`c17f9b5`.
- **`sitemap.ts` uses a stable `CONTENT_REVISED` date, not `new Date()`** — a per-request `lastmod` tells Google every page changed "today" on every fetch, wasting crawl budget. Bump `CONTENT_REVISED` when programmatic content materially changes; blog posts keep their own real dates.
- New clusters that are thin/templated should follow the same judgment: if they'd add hundreds of near-duplicate URLs, ship them `noindex` + out of the sitemap until the domain can support them.

## Sample vs. real reports (`/report/[id]`)

`src/app/(site)/report/[id]/page.tsx` is a Server Component that branches on whether the VIN matches a curated entry in `src/lib/sample-reports.ts`:

- **Sample VINs** (4 curated, fictional VINs — not decodable via the live GoodCar API) get indexable metadata (`robots: index/follow: true`), a visible "Sample report" label, and `sampleReportLd()` schema (`CreativeWork`, explicitly illustrative — never `Product`/`Vehicle`, never `AggregateRating`). `src/app/robots.ts` has a matching `allow` carve-out for exactly these 4 paths.
- **Every other VIN** (a real or potential customer's report) gets generic, non-identifying metadata and `robots: index/follow: false`. `robots.ts` disallows crawling `/report/` broadly; the per-route `noindex` is defense-in-depth beyond that.
- The actual UI/fetch/checkout logic lives in `src/components/report/ReportView.tsx` (client component). It accepts an optional `sample` prop — when present, it skips the live `/api/preview` fetch and renders the curated static data instead. **Do not add new sample VINs without also adding them to `SAMPLE_REPORTS`** — that's the single source of truth used by the homepage cards, the report page, `robots.ts`, and `sitemap.ts`.

## Payment / checkout logic — hands off unless explicitly asked

`TrialCheckout.tsx`, `UnlockedReport.tsx`, `ManageSubscriptionButton.tsx`, everything under `src/app/api/checkout/`, `src/app/api/webhooks/`, `src/lib/goodcar.ts`, `src/app/api/preview/route.ts`, `src/app/api/report/route.ts` are the entitlement/billing core. Changes here have real financial/legal consequences (Stripe subscriptions, GoodCar API costs) — don't refactor incidentally while working on adjacent UI/SEO work.

- `/data-sources` — the methodology page. If a new data provider or report section is added to the product, update this page so the "what we check" claims stay accurate.
